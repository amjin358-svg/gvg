# 001 — Product Requirements Document (PRD)

## 1. Goals

1. Launch a production-ready Trade OS foundation for Global Vista Group.
2. Enable buyers and suppliers to complete RFQ → Quote → Order flows.
3. Provide operational modules for inventory, warehouse, logistics, and customs.
4. Expose an AI Procurement Assistant for matching, drafting, and cost estimation.
5. Support multi-role enterprise access with clear permissions.

## 2. Non-goals (v1.0 foundation)

- Full ERP GL posting and bank reconciliation automation
- Carrier API integrations for every region
- Multi-tenant white-label reseller console
- Native mobile apps (responsive web first)

## 3. Personas

| Persona | Needs |
|---|---|
| Guest | Browse catalog, news, brand story |
| Customer / Business Customer | RFQ, orders, tracking, portal |
| Supplier | Catalog, quote response, fulfillment |
| Sales | CRM, quotes, account ownership |
| Purchasing | Sourcing, RFQ matching, OEM programs |
| Warehouse | Inventory accuracy, pick/pack readiness |
| Finance | Invoice visibility, settlement status |
| Admin / Super Admin | Roles, CMS, module health |
| AI Agent | Tool access for procurement assistance |

## 4. Functional requirements

### 4.1 Marketplace

- Browse products, categories, brands
- Product detail with MOQ, lead time, origin, compliance tags
- News / CMS-managed content

### 4.2 Trade cycle

- Create and manage RFQs
- Collect and compare supplier quotes
- Convert accepted quotes to orders
- Track order status through delivery

### 4.3 Operations

- Inventory visibility by SKU
- Warehouse capacity / utilization
- Multi-modal shipment tracking
- Customs document packet preparation

### 4.4 Intelligence

- AI supplier matching
- RFQ draft generation
- Landed-cost estimation
- HS classification assistance (later with OCR)

### 4.5 Administration

- Role matrix visibility
- Module registry
- Content management entry points

## 5. Non-functional requirements

| Area | Requirement |
|---|---|
| Type safety | Strict TypeScript, no `any` |
| Architecture | Server Components first, repository pattern |
| Accessibility | WCAG AA |
| Responsiveness | Mobile + desktop |
| SEO / GEO | Metadata, sitemap, robots, structured content |
| Observability | Sentry + OpenTelemetry (Phase 2+) |
| Security | AuthN/AuthZ via Supabase + RLS |
| Performance | Static where possible; edge-friendly APIs |

## 6. Acceptance criteria (foundation)

- [x] 20 module routes available
- [x] Demo catalog / RFQ / order / logistics data
- [x] AI assistant demo panel
- [x] Enterprise folder + docs structure
- [ ] Supabase auth + RLS
- [ ] Persistent RFQ/quote/order CRUD
- [ ] Production analytics instrumentation

## 7. Risks

- Customs/HS accuracy requires expert review loops
- Multi-currency FX rates need reliable providers
- Supplier onboarding quality affects marketplace trust
